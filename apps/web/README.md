# @redan/web

The playable prototype: a portrait-canvas parcel editor over `@redan/sim`, per [doc](../../docs/redan-project-doc.md) §8.1/8.2. Vanilla TypeScript + Vite — no framework, no canvas library, so the renderer stays close to a one-file port to `react-native-skia` later (doc §8.2's whole point).

## Status

Two modes, one store/Test-button/verdict-panel scaffolding.

**Tray mode** (the original slice). Loads all 5 `@redan/content` example parcels (imported directly as JSON — this app has no runtime dependency on `@redan/content` itself, since its loaders use `node:fs` and aren't browser-safe), starting each from its pre-built example design (doc §2: "never start from a blank canvas"). Tray-based placement (click a tray shape to arm it, click the canvas to place at the nearest 8-yard grid cell, click a placed piece to remove it, a rotate button while armed), a Test button that runs `grade()` and shows the doc §5 star/coaching verdict plus every golfer's curved route.

**Land mode** (new). Loads 6 seeded-generated natural parcels (`@redan/content/land/*` — hills, water, trees, no hand-authored fairway) and reduces placement to one lever: drag the green. The fairway routes itself live from wherever the green sits (`@redan/sim`'s `deriveFairway`) and renders as 2-yard tiles at 4 screen px (doc §6.4/§8.2), colored straight from `@redan/sim`'s own `lieAt` so the picture is never out of sync with what `grade()` would actually score. Each surface carries its own 1-tile inner rim (sand lip, shoreline, green collar, fairway mow line) so boundaries actually read, and turf gets a deterministic hash-noise speckle plus a low-frequency mottled patch rather than a uniform dither. Drag with mouse or touch (`pointerdown`/`pointermove`, `setPointerCapture`) — the doc's primary target is a phone, and this is the one place in the app that isn't mouse-only.

## What's here

- **`src/render/surface.ts`** — the tiny renderer surface (`fillPolygon`/`strokePolyline`/`fillCircle`/`drawText`/`drawPixelBuffer`/`resize`) doc §8.2 calls for. `src/render/canvas2d.ts` is the *only* file that touches `CanvasRenderingContext2D`; it reuses one backing store across renders (`resize()` early-returns when nothing changed) rather than reconstructing a `Canvas2DSurface` per frame — necessary once a render can fire on every pointermove. `drawPixelBuffer` blits a whole art-resolution RGBA buffer via `putImageData` + a scaled `drawImage` (nearest-neighbor) rather than issuing a fill call per tile — also the skia-portable shape (`Skia.Image.MakeImage` + `drawImageRect`) a per-tile fill never was.
- **`src/render/palette.ts`** — the one place every renderer gets its lie colors from: a `{base, shade, patch, rim}` tuple per `LieType`, plus one decorative-only extra (`NATIVE_AREA_PALETTE`) for `native-area` fixed regions — those score identically to plain rough (`lieType: "rough"`, same distance/dispersion factors) but get their own golden/fescue tone in `grid.ts` so they read as an intentional feature instead of blending invisibly into ordinary rough.
- **`src/render/texture.ts`** — deterministic, position-sampled noise (`hash2`, `valueNoise2`, `fbm2`) for land mode's turf speckle/mottle. Not `@redan/sim`'s `createRng`: that's a sequential stream RNG, and texture needs the same tile to always produce the same value regardless of visit order. `fbm2` sums three octaves at a non-integer lacunarity (2.17) with per-octave coordinate offsets — an earlier two-octave version, at the low base frequency `grid.ts` used to call it with, produced a lattice of large soft-edged squares (the octaves' cell boundaries lined up) rather than organic mottle; both the frequency (in `grid.ts`) and the octave count/offsets (here) changed together to fix it.
- **`src/render/parcel.ts`** — draws a parcel/design (+ optional graded traces) onto a `Surface`: the corridor ribbon (`@redan/sim`'s `offsetPolyline`, so it actually bends), fixed regions, placed pieces, elevation mounds, tee marker, and each golfer's curved flight path. Also owns the world↔screen coordinate math (`PX_PER_YARD`), land mode's art tile size (`YARDS_PER_TILE`/`PX_PER_TILE`) kept independent of the doc §6.4 design snap grid (`DESIGN_SNAP_YARDS`, what `snapToGrid` uses), and `computeLandBounds` (land mode's *fixed* frame, independent of the green's current position — dragging must never resize the canvas mid-drag).
- **`src/render/grid.ts`** — land mode's rasterizer (doc §6.4: "cells... deterministic per-cell dither"). A three-pass build of one RGBA buffer: classify (one `lieAt` sample per tile — sim-truth, queried through the same `compileTerrain` assembly `grade()` uses, and never rewritten by a later pass), rim (does this tile border a different lie — a decoration flag only), colorize (turf texture + rim color + a once-per-parcel-load hillshade layer (`buildHillshade`) multiplied in, so elevation actually reads as terrain instead of a faint ring). `paintRaster` blits the whole buffer in one `Surface.drawPixelBuffer` call.
- **`src/editor/state.ts`** / **`src/editor/intents.ts`** — a minimal store plus intent functions (`placeAt`, `removePieceAt`, `armShape`, `rotateArmed`, `selectParcel`, `runGrade`) instead of raw pointer-event handlers, per doc §6.3's `place(shapeId, cell, rot)` framing. Undo/replay/share-a-layout would fall out of recording these, none of which is built yet.
- **`src/editor/land.ts`** — land mode's intents: `selectLandParcel`, `moveGreen` (clamps the drag inside the land, inset by a margin — `@redan/sim`'s round loop has no exit besides reaching the green, so a green dragged onto the OB frame would either never resolve or resolve nonsensically — then pushes the target away from any `fixedRegions` hazard it would overlap, since a hazard always wins a lie-resolution tie against the green and would otherwise eat a real bite out of it, not just a visual one), `runLandGrade` (derives the fairway, then grades).
- **`src/ui/tray.ts`** / **`src/ui/verdict.ts`** — the bottom tray strip (hidden in land mode — there's nothing to arm) and the star/coaching-sentence/golfer-table panel. `verdict.ts` caps land mode at ★★ (`maxStars`) rather than showing an unearned third star, since `grade()` never counts the green against the budget (see `@redan/sim`'s README) and a mode with nothing else to spend has no restraint to demonstrate — the panel says so in a sentence rather than gating silently.

## Known simplifications worth revisiting

- **Grading is synchronous on the main thread.** Doc M1's target is sub-500ms; a `grade()` call over the current 7-golfer roster visibly freezes the tab for a couple of seconds during interaction testing. The doc's own plan is a Web Worker (`src/sim/worker.ts`) — not built in this pass. Land mode makes this more visible, not less: derived corridors bend by construction, which roughly doubles `searchRoute`'s combinations. Don't ship this as-is past a prototype.
- **No dispersion ovals yet** (doc §6.4's "each archetype's landing zone shows as a translucent ellipse"). `grade()` doesn't currently return the sigma values needed to draw one live while dragging a piece — only the realized trace of one trial. Would need a small `GradeResult` extension or a cheap client-side re-derivation.
- **Tray placement is click-to-arm-then-click-to-place, not drag-and-drop** (land mode's green *is* drag-and-drop — this simplification is tray-mode-only now). Doc §6.4 describes actual dragging with live-updating dispersion ovals for the tray flow too.
- **JSON parcels are imported by relative path** (`../../../packages/content/parcels/*.json`, `.../land/*.json`) rather than through a shared package export, since `@redan/content`'s loaders are Node-`fs`-based and not browser-safe. Fine for 5+6 example parcels; won't scale to real campaign content without a proper content-serving story.
- **Land mode's rasterization is only cached one cell deep** (keyed on the green's currently snapped 8-yard cell) — good enough for a slow drag where most pointermove events land in the same cell as the last, not stress-tested against a fast flick across the whole parcel.
- **Land envelopes are constant-width rectangles** (`@redan/sim`'s `LandEnvelope`) — no tapering, no non-rectangular boundaries; `lieAt`'s land-mode OB test and `deriveFairway`'s fringe-band construction both assume the rectangle shape specifically.
- **The green-vs-hazard push (`editor/land.ts#pushOutOfHazards`) only runs on drag**, not on a parcel's freshly generated starting green position — `packages/content/scripts/generate-land.mjs` doesn't yet apply the same clearance guarantee when it authors the initial `design.pieces[0]`, so a freshly loaded parcel could in principle start with the green already touching a hazard (untested; the generator's hazard placement bias keeps them away from the default `y = 0.6 * length` start in practice).
- **`native-area`'s decorative texture has no rim.** `grid.ts`'s rim pass only compares `LieType` ids, and `native-area` shares `"rough"`'s id, so its boundary against plain rough is a flat texture change, not an outlined seam (it still gets `rough`'s usual rim where it borders a genuinely different lie, like fairway).
- No accounts, no progress persistence, no mobile-specific layout tuning beyond a responsive flex layout (doc M1's actual mobile-portrait spec — tray strip under the thumb, verdict as a sliding sheet — isn't implemented).
